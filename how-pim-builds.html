How the feed is built

For the developer. Start from an empty Pimcore. Each picture is one step that already exists. Plain sentence first, then the rule. JSON for each call is on the payload page. The Red Horse explanation is a separate page.

0. Start from nothing

Before any F&O call, Pimcore does not know Red Horse products. It also does not yet know the shape of a screw. The Function cannot create that shape.

Empty

No screw class. No colour list. No folders. No products. A push now would have nowhere to land.

After the script, still no products

The shelves exist: screw, washer, head type, material, corrosion, colour, size, length. The shelves are empty of Red Horse data.

2. Two trees. The feed writes only one.

/TypeBasedCatalog

The workshop. People use it to try the screens. The F&O calls never write here. A colour code that already lives here is reused, not renamed.

/ErpSync

Everything the Function creates.

3. Then the calls, in this order

Each box needs the one above it. A repeat with the same key updates the same object. It does not create a second one. A missing key on the request is HTTP 401.

Check
/auth says the key is accepted. /ping stores the raw JSON under /ErpIntake. Ping creates no company and no product.
↓
/companies
Match companyCode. Creates PtLegalEntity. Allowed: RH RHU ASW SPI. Skipped, not a failure: GXN DH DE DE2 and unknown. This does not turn a company into a shop. JSON
↓
/dimensions
Match dimension + code. Example code 59, name RAL 1003. Four lists only: config, colour, size, style. A group later named DIMENSIONS is not this call. JSON
↓
/tree
Match categoryKey. Five folders, parents first. Level 1 productType 06 or 09. Anything else is skipped. Children inherit the class. texts[] on the folder is accepted and not stored. Those are folder labels, not the product name. JSON
↓
/attribute-definitions
Once, when setup changes. Codes, type, unit, texts, options, groups, and which folder uses which group. Does not write a product value. Use RH_Head, not HEAD TYPE. Language ids are stored as sent. JSON
↓
/products
Master match code, parent is the level-5 folder. Variant match itemNumber plus masterItemNumber. Also the master’s allowed colour, size, config, and style. washerItemNumber is ignored. No attribute values here. JSON
↓
/product-attributes
Match itemNumber that already exists. Writes the facts. See the next picture for where each fact lands. JSON

The A2 and C4 pictures are not created by the feed. They are uploaded on the material lookup and the corrosion lookup.

Fixed in Pimcore, or sent by F&O

Fixed. Not a map in the payload.

Two classes. Seven levels. Screws have config, colour, size, style. Washers have size only. Known codes fill the fields in the table above. Only 06 and 09 are accepted. A payload cannot invent a class. Icons and Danish or Swedish shop text stay in Pimcore.

Sent on the batch.

Company rows. Dimension codes and names. Folder ids. Which folder uses which attribute group. Option codes such as HX17. Product rows. The master’s allowed lists. A code with no field is stored on the named folder and is not moved upward.

Rules on every write

RuleMeaning
Match keyCompany code, folder id, dimension code, master code, or item number. Never a Pimcore id.
Field left outKeep the current value.
null, blank, spacesClear that value.
isDeleted: trueUnpublish. Do not delete. On an attribute it clears that attribute only.
Missing parent or itemThat row fails and can be retried. The rest of the batch still applies.
SkipNot a failure. ok is true only when failed is 0.
Size500 rows or 2 MB. Split a larger batch. Unknown extra keys are ignored.

Not built

  • /released returns 404. Shop on/off is not written. Do not treat “stopped for sales” as shop off.
  • /translations returns 404. Product name and description per F&O language are not stored. Folder texts[] on /tree are also not stored. They are folder labels, not this call. Danish and Swedish shop copy is written in Pimcore. The one product name is name on /products.
  • washerItemNumber is accepted on /products and ignored.
