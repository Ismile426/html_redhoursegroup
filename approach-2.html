Approach 2 — what F&O sends

Chosen by Red Horse. F&O and PIM each keep their own folders. A link in PIM joins one PIM folder to one F&O category. Products are still created in F&O. Nothing on this page is a new live call.

No existing call is removed. The eight calls below stay. Two fields are agreed and are not on TEST yet. The three calls from PIM back to F&O are not built.

Calls that stay

CallStatusWhat F&O does
/companies No change Company code and name. Shop companies remain RH, RHU, ASW, SPI.
/dimensions No change Allowed configuration, colour, size, and style for ticked masters. Do not add other dimensions.
/tree Keep sending Screws categories only, as today: record id, parent, name. Do not stop this call. It still builds the PIM folders until the link list is stored separately. We will say when that split is on TEST.
/attribute-definitions No change Keep sending every definition, including option codes and the en-US option text. PIM does not take over the pick-lists.
/product-attributes Keep until the switch date Still sent. On the switch date, the agreed attributes are left out of the row and are never sent empty. That date is not set. A value is stored only when the product sits under a folder that has that attribute group.
/product-translations No change Name and description per language, as today.
/product-master One change, not on TEST Today a new master still needs parentKey. When TEST is ready: no parentKey puts a new master in a holding folder. See below.
/product-release One field, not on TEST Today: item number, company, released true or false. lifecycleState is not stored yet. Do not send it until we say so.

Not on TEST yet

CallAgreed rule
/product-master
  • A new master with no parentKey is stored in an unmapped holding folder.
  • productType is required on that create, on the master only: "06" or "09". Not on variants.
  • Any other value, or a missing type, is skipped. The product is not created. It is not defaulted to a screw.
  • A later row with no parentKey leaves the product in the folder a person moved it to.
  • The same type on an update changes nothing. A different type is rejected. Placement does not convert a screw into a washer.
/product-release
  • On released: true, store lifecycleState as "1", "2", "3", or null.
  • On released: false, leave the field out.
  • The code is stored as sent. It does not turn the shop off. The shop still follows released.

Do not start a full reload for these fields. We will say when each one is on TEST.

What the holding folder does not do

  • It is not mapped to an F&O category. No placement is sent back for a product that is still there.
  • Attribute values sent while the product is still there are ignored. Send them after a person has placed the product under a folder that has the attribute group.
  • released: true for RH, RHU, ASW, or SPI still turns that shop on in PIM, including in the holding folder. PIM does not feed Magento.

New calls — not built

PIM will call the Function App directly. These calls do not go through the Data Lake. Nothing here is live.

OrderCallWhat PIM sends
1 Attribute set-up The agreed attributes only, and which F&O category uses them. The category id is the same categoryKey as /tree.
2 Placement The master item number and that F&O category id. Sent only when the mapped category changes. Variants are not sent; they follow the master in F&O.
3 Attribute values The full set the master shows, including a value it shows from a folder above. A missing value is removed in F&O. A product that does not yet have the full set is left out.

PIM does not send its folders, its tree, variant attribute values, or new item numbers. The Function App does not keep a second map. It uses the category id in the body. No return call starts until one writer per value is proven on TEST.

Link

  • The link lives in PIM. One PIM folder, one F&O category id. Several PIM folders may share one id.
  • A rename or a move of the PIM folder does not change the link. The link changes only when that folder should point at a different F&O category.
  • A product move is sent back only when the new folder maps to a different F&O category.
