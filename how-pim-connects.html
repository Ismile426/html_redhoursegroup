How F&O connects to Pimcore

23 Sep 2026. What is live today, in plain language and then as a build reference. The exact JSON for each call is on the payload page. This page does not replace that contract.

For Red Horse For the developer Fixed in Pimcore / sent by F&O Rules on every call Not connected yet

For Red Horse

Pimcore does not look inside F&O. A small program on the F&O side (the Azure Function) pushes a batch of JSON into Pimcore. Pimcore stores it as catalogue folders and products. People in Pimcore then add the pictures, the Danish and Swedish shop text, and the catalogue icons.

In one sentence

F&O says what the product is. Pimcore holds it in a fixed shape and adds the selling text and the pictures.

The address

TEST is http://10.100.16.4:82/api/v1. That address is on the Red Horse network only. Azure cannot reach it yet. Every call sends a header X-API-Key. There is no login session.

The order that is live

Each box is one call. The next box needs the one before it. A repeat of the same call updates what is already there. It does not make a second copy.

1. CompaniesWhich F&O companies exist
2. DimensionsThe colour, size, config, style lists
3. FoldersType, family, series, range, drawing
4. Attribute setupWhat a fact is, and which folder uses it
5. ProductsThe master and the SKU you can order
6. Attribute valuesThe head, the material, the length

Shop on/off and product texts in several languages are not in this row. They are listed under Not connected yet.

What a screw looks like after those calls

One screw is seven levels. The top five are folders. The last two are the product and the thing a customer orders.

TypeScrews, or washers. Call: folders.
FamilyThe brand, such as CREO. Call: folders.
SeriesHead type lives here. Call: attribute values.
RangeMaterial, coating, corrosion. This is the category. Call: attribute values.
Product groupThe drawing. Diameter and drill cap. Call: attribute values.
MasterOne product, many lengths. Length lives here. Call: products, then attribute values.
VariantThe orderable item: colour, size, and so on. Call: products.
What a person sees

After the folder call, the tree exists but the products are empty. After the product call, the master and the variant exist, still without head type or length. After the attribute-value call, the series shows the head, the range shows material and corrosion category, the drawing shows the diameter, and the master shows the length. The variant does not get its own head type. It shows the series head.

What F&O does not send

These stay typed in Pimcore:

  • The catalogue icon on a material (the A2 badge) and on a corrosion category (the C4 badge). F&O sends the code. A person uploads the picture.
  • Danish and Swedish shop title and shop description.
  • Technical pictures, pack labels, and certificates.

For the developer

Same connection, from an empty Pimcore. Do this in order. The JSON for each step is the matching tab on the payload page.

  1. Build the classes before any F&O call.
    Plain
    Pimcore must already know what a screw is, what a washer is, and which shelves exist. The Function does not create those shelves.
    Technical
    app:load-kalle-type-demo creates PtScrew and PtWasher, the lookup classes (head type, material, corrosion category, colour, size, and the rest), the measure store, and the shop bricks. It does not load Red Horse products. Do not run it with --force on TEST. That flag deletes the workshop tree.
    F&O objects are written only under /ErpSync. The workshop tree /TypeBasedCatalog is never written by these calls.
  2. Check the key. /auth and /ping.
    Plain
    Auth only says the key is accepted. Ping stores the raw JSON so a person can read what was sent. Ping does not create a company or a product.
    Technical
    GET or POST /api/v1/auth. POST /api/v1/ping writes FoIntakeLog under /ErpIntake. A missing key is HTTP 401 on every route.
  3. Companies. /companies
    Plain
    Creates the company record. It does not turn the company into a shop.
    Technical
    Match key companyCode. Object PtLegalEntity under /ErpSync/LegalEntities. Created today: RH, RHU, ASW, SPI. Skipped, and that skip is not a failure: GXN, DH, DE, DE2, and any unknown code. Repeat with the same code updates the name. isDeleted: true unpublishes it.
  4. Dimension lists. /dimensions
    Plain
    The lists a variant will point at: configuration, colour, size, style. Send the short code and the readable name. Example: code 59, name RAL 1003.
    Technical
    Match key dimension + code. Objects under /ErpSync/DimOptions/<Class>. A code is unique for that class in the whole system. A code already used by the workshop is reused and answered skipped / WORKSHOP_OWNED. The workshop name is not renamed. Send this before products. This call is not attribute groups. A group named DIMENSIONS on the attribute setup is a different thing.
  5. Five folders. /tree
    Plain
    Builds the path the product will hang from. Parents before children. Level 1 must say screw (06) or washer (09). Anything else is skipped.
    Technical
    Match key categoryKey (the F&O record id, as text). Path /ErpSync/Catalog/…. Level 1 productType 06 creates PtScrew; 09 creates PtWasher; otherwise skipped / UNKNOWN_TYPE. Children inherit the class. Empty brand and empty product-group number still create the folder. The level cannot be changed after create. A new categoryKey creates a second folder and leaves children on the old one.
    texts[] on a folder (languageId, friendlyName, description) is accepted and not stored. Those are folder labels. They are not the product name.
  6. Attribute setup, only when setup changes. /attribute-definitions
    Plain
    Says what a fact is (a number, a word, a list), which group it belongs to, and which folder uses that group. It does not put a value on a product. Send RH_Head, not HEAD TYPE.
    Technical
    One document under /ErpSync/AttributeBook. Codes, types (text, decimal, integer, boolean, list), units, texts, and options are stored as sent. en-CA is not folded into en. A list value is legal only if it is one of the option codes on this call. A folder categoryKey that does not exist yet fails that folder row (NOT_FOUND, retryable). The attribute rows in the same batch are still stored. A repeat with the same body answers unchanged.
  7. Products. /products
    Plain
    The master is the product. The variant is the SKU. The master must name the level-5 folder. The variant must name its master. Put the default name on this row.
    Technical
    Master match key code. Variant match key itemNumber, with masterItemNumber. Both under /ErpSync/Catalog, class taken from the level-5 folder. The master also sends allowedConfig, allowedColour, allowedSize, allowedStyle. Omit keeps the list. null or [] clears it. A variant colour outside a non-empty list is not linked and is listed in ignored. Washers only have size. washerItemNumber is accepted and ignored. This call does not write attribute values and does not write shops.
  8. Attribute values. /product-attributes
    Plain
    Puts the facts on the product that already exists. The folder from setup decides the branch. The value lands on the level that owns that fact. It is not moved up onto a folder that was not named.
    Technical
    Match key itemNumber (master code or variant number). Unknown item: NOT_FOUND, retryable. Unknown attribute code, an option that is not on the definition, and a DIAMETER value that contains / go in ignored and do not fail the row. isDeleted: true or a null value clears that attribute only. It does not unpublish the product. A missing attribute in the list is left as it is. Sending the same values again answers unchanged.
    Where a known code is written, when the named folder’s branch contains that level:
    Code sentWhat Pimcore fillsOn
    RH_HeadHead typeSeries folder
    RH_Point, RH_ThreadPoint type, thread typeSeries folder
    RH_SpecialFeaturesOne feature, not split on commasSeries folder
    MATERIAL TYPE, RH_Coating, CORROSION CATEGORYMaterial, coating, corrosion categoryRange folder
    DIAMETER, DRILL CAP MMDiameter, drill cap from, and valueTo as drill cap toProduct group
    RH_DriveDrive size (TX10, HX8, …). Not drive type.Product group
    LENGTH MM, partial length, effective lengthLength, partial length, effective lengthThe master of this item
    DRIVE TYPEDrive type (Torx, Phillips, Pozi). Not RH_Drive.Series folder
    Any other defined codeStored on the folder that was named. No new field is invented.That folder

One screw, followed through

The numbers below are the shape, not a promise that these exact ids exist in TEST. After the six calls, Pimcore holds this:

/ErpSync/Catalog 5637144580 type Screws ← /tree, productType 06 5637144712 family CREO ← /tree, brand … series head type HX17 ← /product-attributes RH_Head … range material A2, corrosion C4 ← /product-attributes 5637145021 product group diameter 6.5 mm ← /product-attributes DIAMETER drill cap 2.5 to 4 35044 master length 23 mm ← /products, then LENGTH MM 35044-… variant colour 59, size 8 ← /products + /dimensions head type is still the series value

The A2 and C4 pictures are not in this tree. They are uploaded on the material and on the corrosion category.

Fixed in Pimcore, or sent by F&O

Plain

The shelves are fixed. F&O fills the shelves. F&O cannot add a third kind of product by sending a new name. A fact Pimcore does not already have a shelf for is kept on the folder, and that is all.

Rules on every call

RuleWhat it means
Match keyCompany code, folder id, dimension code, master code, or item number. Never a Pimcore id. The same key updates the same object.
Leave a field outKeep what is already stored.
null, "", or spacesClear that value.
isDeleted: trueUnpublish. Do not delete the row. On attribute values it clears that one attribute and does not unpublish the product.
Missing parent or unknown itemThat row fails and can be retried. The rest of the batch still applies.
A skipNot a failure. ok is true when failed is 0.
SizeAt most 500 rows, or 2 MB. Split a larger batch.
Extra keysIgnored. They do not fail the row.

Not connected yet

Do not treat these as live
  • /released — which shop sells the SKU. POST returns 404. Shop bricks stay as they are. Do not treat “stopped for sales” as shop off.
  • /translations — product name and description per F&O language (en-CA, en-HK, …). POST returns 404. This is not the folder texts[] on /tree. Folder texts are labels of the folder. Product texts are this call. Neither is stored. Danish and Swedish shop copy is still written in Pimcore. The single product name is the name on /products.
  • washerItemNumber on /products — accepted and ignored until F&O confirms it is the washer’s own item number.
