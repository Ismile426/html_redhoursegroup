DO NOT BUILD Lookups — not an F&O feed yet

PIM already has lookup objects (PtColourOption, PtSizeOption, head type, brand, and the rest). A variant points at one by code. The readable name sits on that object.

Filling those objects is PIM master data until Red Horse says F&O is the source of the code and the name. Do not build /dimensions or /lookups. Send the axis value on the variant row in /products, and named values on /attributes.

DO NOT BUILD /translations

Do not POST language packs. Product name is one field; put it on /products if F&O has a single name. Shop text in en / da / sv is written in PIM. F&O locales such as en-CA and zh-Hant are not PIM languages.

Do not POST /attribute-setup

Attribute groups exist in PIM. They are fixed on the class. F&O does not send them. F&O sends values on /attributes.

Attribute setup (your /attribute-setup)Attribute values (/attributes)
WhatDefinitions, data types, pick-lists, groups, and which folder/layer uses which groupOne item’s actual value: Head type = Torx
Who owns itPIM — set once in the classF&O — sent per item
How oftenOnce (changes on a schema change)Every product run

Why F&O does not send the setup

In this model, which group sits on which layer is fixed in the class: Product-Group measures on the Product Group tab, Master measures on the Master tab, Range geometry on the Range tab. The class says literally “groups for this layer only, children inherit, cannot add/remove groups.” It is not chosen per folder at runtime.

Your folderGroups[] (“folder X uses groups A, B”) assumes F&O assigns groups to folders. If F&O sent that nightly, it would try to redefine PIM’s schema and duplicate our locked groups. F&O keeps sending values only.

Reply shape — companies, tree, and later write APIs

HTTP 200 = request applied. Inspect results and errors. 400 = nothing applied. 413 = split. 401 = bad key.

What is not an F&O feed — and why

These were in your HTML. Do not build them. PIM work (shop copy, pictures) is not listed here — it is not a Function job.

DROP /units (PCS / BOX, factor 100)

Order/packing quantities. Pimcore is not the order system; price and stock already stay out. Catalogue measure units (mm / in) already sit on the CS key. Send Length as F&O stores it ("35.00 mm") on /attributes; we parse it.

HOLD /barcodes

There is no barcode / EAN / GTIN field on PtScrew / PtWasher. Not a “no” — a “model it first.” If Red Horse wants EAN in PIM, we add the field, then take the feed.

HOLD /relations (accessory / alternative / sparePart)

Those types are not fields today. The one product-to-product link we have is washerProduct on a screw SKU (“with washer”). Cross-sell/related is a modelling decision with Red Horse, then a feed. Not v1.
