Auth on every call. Header X-API-Key (also Authorization raw / Bearer / ApiKey). HTTP 401 = missing/wrong key — do not retry the same value. Do not put the key in Teams or email. Key Vault name: Pimcore-ApiKey-Test.
Write APIs: wrapper { "batchId", "items": [] } preferred; bare array also accepted. Max 500 items / 2 MB → HTTP 413. HTTP 200 on write = applied (inspect results / errors). Ping 200 = stored only.

Shared write response

FieldMeaning
oktrue only if failed === 0. Expected skipped does not fail the batch and is not in errors.

results[].actioncreated | updated | unpublished | skipped | failed

Omit a field = keep. null = clear. isDeleted: true unpublishes (not a hard delete). 5xx / timeout: send the same batch again (upsert).

2. POST /api/v1/tree — LIVE local + TEST :82

F&O Product Catalogue folders. Not masters, variants, attributes, or shops. Same class down the branch (PtScrew or PtWasher). Objects file under /ErpSync/Catalog — workshop /TypeBasedCatalog is not touched.

Guess we built with (C7) — tell Kalle

  • Type row productType 06 / screw / screws → PtScrew.
  • 09 / washer / washers → PtWasher.
  • Anything else → skipped / UNKNOWN_TYPE (not a batch failure).
  • Children inherit class from the parent. We do not map class from the English folder name alone (TEST names are not final).
  • C10: empty brand / productGroupNumber still creates the node.

Request

Send parents before children. categoryKey = F&O record id as text (same id products will use as parentKey). Do not send "06", "CREO", or "063333" as categoryKey.

FieldRequiredRule
categoryKeyYesMatch key. PIM code. String rec id.
parentKeyCreate of a child: yes. Root: null or omit.Parent’s categoryKey. Omit on update = do not move. null on update = move to catalog root.
layer or levelCreate: yes. Update: omit = keep.Prefer layer. level 1=type … 5=productGroup. Both sent and they disagree → VALIDATION. master/variant → VALIDATION (use /products).
productTypeType row on create06 or 09 now (not a later change). Children omit; class is inherited. Missing / unknown → skip UNKNOWN_TYPE.
nameNoCreate default = categoryKey. null clears.
brandNoFamily. Lookup by code. Missing lookup → leave empty, still create.
productGroupNumberNoDisplay / PG field. Not the match key.
isDeletedNotrue unpublishes.
code, isActive, texts[]NoIgnored in v1. You may send them; PIM does not store folder translations or F&O active here.

Do not send head type, measures, images, item numbers, or shops on this feed. Layer is frozen after create (CONFLICT if you change it). No synthetic folders if F&O skips a level.

What you should not send on /tree

  • Pimcore object ids, class name, kl_* measure keys.
  • Head type / material / images / shops / released / item numbers.
  • A Magento-style Category object — PIM has none.
