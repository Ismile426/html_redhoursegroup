Order & rules

One tab = one POST body. Do not mix fields between tabs.

Feed order

  1. /companies
  2. /dimensions — so variant colour and size resolve to a name
  3. /tree — parents before children
  4. /products — masters before variants
  5. /attributes · /released · /translations

Reply shape — same for every write

HTTP 200 means the request was applied; read results and errors. 400 nothing applied. 413 split the batch. 401 bad key.

FieldMeaning
oktrue only when failed is 0. A skip does not fail the batch.
processedRows created, updated, or unpublished.
failedUnexpected failures only.
results[].actioncreated | updated | unpublished | skipped | failed
errors[].errorThe message field is called error. Decide retries from code and retryable, not from this text.
{
  "ok": false, "processed": 1, "failed": 1,
  "results": [
    { "key": "35044", "action": "created" },
    { "key": "35047", "action": "failed", "code": "NOT_FOUND", "retryable": true,
      "error": "parentKey not found; send parents first" }
  ],
  "errors": [
    { "key": "35047", "code": "NOT_FOUND", "retryable": true,
      "error": "parentKey not found; send parents first" }
  ]
}

Your own example showed ok: true alongside failed: 1, and used message instead of error. Those two differ from what Pimcore returns.

Not v1

/attribute-setup — content yes, endpoint no

Two different things are mixed in this call. Attribute definitions — names, data types, units, pick-list values — are exactly what we need, and we need them once, as a list. Attribute groups and which folder uses which group is Pimcore structure: it is fixed on the class per level, children inherit it, and it cannot be added or removed at runtime. A nightly POST cannot change that, so please do not build it.

/units — hold

Measure units such as mm and inch already sit on the Pimcore measure field, so a conversion table is not needed for the catalogue. Pack size — a box of one hundred — is a real shop fact, but there is no field for it in Pimcore today. If Red Horse wants it, we add the field first.

/barcodes — hold

There is no barcode field on the product classes. Not a refusal: model it, then feed it.

/relations — hold

Accessory, alternative, and spare part are not fields today. The one product-to-product link that exists is the washer on a style-W screw, which belongs on /products. Cross-sell is a Red Horse decision first.

Never sent

Price and stock.
