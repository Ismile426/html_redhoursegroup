F&O → Pimcore — live API

Updated 21 Sep 2026. One tab = one call. This is what PIM requires in code today. TEST: http://10.100.16.4:82/api/v1 (RH LAN). Azure cannot reach Pimcore yet — this page is the public contract.

LIVE: /auth · /ping · /companies · /tree. Open the matching tab. Extra JSON keys are ignored.
X-API-Key on every call — /auth is not a login. Do not put the key in Teams. Max 500 rows / 2 MB → HTTP 413. Wrapper { "batchId", "items": [] }.

LIVE GET/POST /api/v1/auth

Key check only. No body. No objects written. Not a session — send X-API-Key again on companies and tree.

Required

FieldWhereRule
X-API-KeyHeaderEvery call. Also accepted: Authorization raw / Bearer / ApiKey.

Request

GET or POST http://10.100.16.4:82/api/v1/auth
X-API-Key: <key>

Response

HTTP 200
{ "ok": true, "service": "pimcore", "auth": "api_key", "principal": "erp-integration" }

HTTP 401
{ "ok": false, "error": "unauthorized", "auth": "api_key" }

401: do not retry the same key.

Dry-run. Stores the raw JSON under /ErpIntake so we can see your payload. Does not create companies or folders. HTTP 200 = received, not applied to the catalogue.

Required

FieldRule

BodyAny JSON, or empty. Over 64 KB is truncated, still 200.

Request

POST http://10.100.16.4:82/api/v1/ping
X-API-Key: <key>
Content-Type: application/json

{ "batchId": "dry-run", "items": [ { "note": "any json is fine" } ] }

Response

  "message": "Stored. Open Data Objects → /ErpIntake in admin.",
  "objectId": 123, "path": "/ErpIntake/...", "summary": "..." }

objectId here is a log object, not a company.

LIVE POST /api/v1/companies

Upsert shop companies. Match companyCode. Create: RH, RHU, ASW, SPI. Skip (not a failure): GXN, DH, DE, DE2, unknown. No shop bricks. languageId ignored.

Required / optional

FieldRequiredRule
companyCodeYesMatch key. F&O company id.
nameNoOmit = keep. null = clear. Missing on create uses a default name.
isDeletedNotrue unpublishes (not a hard delete).

LIVE POST /api/v1/tree

Product Catalogue folders only (type → family → series → range → product group). Not products, not attributes, not shops. Parents before children.

Must send on every level-1 row: productType "06" or "09". Without it the root is skipped (UNKNOWN_TYPE) and children have no parent. F&O folder code like SCR is not this field.

Required / optional

FieldRequiredRule
categoryKeyYesF&O record id as text. Match key. Not "06" / "CREO" / PG number.
parentKeyChild: yes. Root: nullParent’s categoryKey. Omit on update = do not move. null on update = catalog root.
layer or levelCreate: yesPrefer layer. level 1=type … 5=productGroup. Both sent and they disagree → VALIDATION.
productTypeType row (level 1) on create06 = screw, 09 = washer. Children omit (inherit). Unknown → skip.
nameNoCreate default = categoryKey.
brandNoFamily. Empty still creates the node.
productGroupNumberNoDisplay only. Not the match key.
isDeletedNotrue unpublishes.
code, isActive, texts[]NoIgnored in v1. Safe to send.

Request

POST http://10.100.16.4:82/api/v1/tree
X-API-Key: <key>
Content-Type: application/json

{
  "batchId": "adf-tree-001",
  "items": [
    { "categoryKey": "5637145001", "parentKey": null, "layer": "type", "level": 1,
      "productType": "06", "name": "Screws", "isDeleted": false },
    { "categoryKey": "5637145002", "parentKey": "5637145001", "layer": "family", "level": 2,
      "name": "CREO", "brand": "CREO", "isDeleted": false },
    { "categoryKey": "5637145003", "parentKey": "5637145002", "layer": "series", "level": 3,
      "name": "Pan-head TX", "isDeleted": false },
    { "categoryKey": "5637145004", "parentKey": "5637145003", "layer": "range", "level": 4,
      "name": "Range 15546", "isDeleted": false },
    { "categoryKey": "5637145005", "parentKey": "5637145004", "layer": "productGroup", "level": 5,
      "name": "PG 063333", "productGroupNumber": "063333", "isDeleted": false }
  ]
}

Success

HTTP 200
{
  "ok": true, "batchId": "adf-tree-001", "processed": 5, "failed": 0,
  "results": [
    { "key": "5637145001", "action": "created", "path": "/ErpSync/Catalog/5637145001" }
  ],
  "errors": []
}

Skip (not a failure)

{ "ok": true, "processed": 0, "failed": 0,
  "results": [{ "key": "…", "action": "skipped", "code": "UNKNOWN_TYPE", "retryable": false,
    "error": "productType is not 06 (screw) or 09 (washer); not created" }],
  "errors": [] }

Row failure (rest of batch still applies)

{ "ok": false, "processed": 1, "failed": 1,
  "results": [
    { "key": "5637145001", "action": "created" },
    { "key": "5637145002", "action": "failed", "code": "NOT_FOUND", "retryable": true,
      "error": "parentKey not found; send parents first" }
  ],
  "errors": [{ "key": "5637145002", "code": "NOT_FOUND", "retryable": true,
    "error": "parentKey not found; send parents first" }] }
codeWhenretryable
VALIDATIONMissing categoryKey; bad/missing layer on create; layer vs level clash; master/variant on this feedfalse
NOT_FOUNDParent not in PIM yettrue
UNKNOWN_TYPEType row not 06/09 — skipped, not in errorsfalse
CONFLICTLayer change after create; save errorlayer change false; save true

Do not send head type, measures, images, item numbers, shops, or Pimcore ids on this feed. Layer cannot change after create. Rename only: send categoryKey + name, omit parentKey.

Reply shape — same for companies and tree

HTTP 200 means the request was applied. Inspect results and errors. HTTP 400 = whole request not applied (bad JSON). 413 = split the batch. 401 = bad key.

FieldMeaning
oktrue only if failed === 0. Skips do not fail the batch.
processedcreated / updated / unpublished
failedUnexpected only
results[].actioncreated | updated | unpublished | skipped | failed
results[].keycompanyCode or categoryKey
errors[].errorEnglish text — parse code + retryable, not this string

Omit a field = keep. null = clear. 5xx / timeout: send the same batch again (upsert). Do not use a field named message — it is error.
