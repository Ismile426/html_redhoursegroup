Do not send the new fields yet. parentKey omitted on a new master, productType on that create, and lifecycleState are not on TEST. The three return calls are not built.

The only new case is a master with no folder yet. Omit parentKey. Send productType "06" or "09". It is stored in a holding folder that is not mapped. Do not default a missing type to a screw.

Example — one master with no folder, one master on a folder

{
  "batchId": "a2-master-001",
  "items": [
    { "code": "88001", "layer": "master", "productType": "06",
      "name": "Unplaced screw" },
    { "code": "88002", "layer": "master", "productType": "09",
      "name": "Unplaced washer" },
    { "code": "40100", "layer": "master", "parentKey": "5637150105",
      "name": "Hex head roofing screw 6.5 x 100" },
    { "itemNumber": "88001", "masterItemNumber": "88001", "layer": "variant",
      "name": "Unplaced screw" }
  ]
}
  • 88001 has no parentKey and productType "06". New master, holding folder, screw.
  • 88002 is the same with "09". Washer. It is not turned into a screw.
  • 40100 still has a parentKey. No productType is required. The folder decides the type, as today.
  • The variant uses masterItemNumber. It is created under that master, including a master that is still in the holding folder.
  • A later row for 88001 with no parentKey updates it in place. It does not move.

NOT ON TEST POST /api/v1/product-release

Same as today: one row per variant and company. released: true adds the company. RH, RHU, ASW, and SPI also turn that shop on. released: false removes the company and that shop. The product stays.

lifecycleState is stored per company on the variant. It does not turn the shop off. The shop still follows released. Do not send it until this field is on TEST.
FieldRequiredRule
itemNumberYesThe variant number. A master number is not accepted until a variant with that number exists.
companyCodeYesA company already sent on /companies.
releasedYestrue or false. Same as today.
lifecycleStateNoOn released: true: "1", "2", "3", or JSON null. Stored as sent for that company. null clears the stored state and leaves the shop as released set it. Omit the field and the stored state is left as it is. On released: false, leave the field out. That company’s stored state is removed with the company. Any other value fails the row and writes nothing.

Example

{
  "batchId": "a2-release-001",
  "items": [
    { "itemNumber": "88001", "companyCode": "RH",  "released": true,  "lifecycleState": "3" },
    { "itemNumber": "88001", "companyCode": "ASW", "released": true,  "lifecycleState": null },
    { "itemNumber": "88001", "companyCode": "RH",  "released": false }
  ]
}
  • "3" is stored for RH. The RH shop still turns on, because released is true.
  • null is stored for ASW. The ASW shop still turns on.
  • The same row again, with the same state, comes back unchanged.
  • released: false for RH removes RH and its shop, and removes the stored "3". ASW is left as it was.
  • "lifecycleState": "nope" fails that row with VALIDATION. The shop and the stored state are not changed.

A product in the holding folder is included. released: true for RH, RHU, ASW, or SPI still turns that shop on there. PIM does not feed Magento. "3" does not mean the shop is off.

NO CHANGE POST /api/v1/product-attributes

Same body as today. Send it after /product-master.

A value sent while the product is in the holding folder is ignored and not kept. The reply names the code and says it is not placed on a folder of this item. Send the values again after a person has placed the product under a folder that has that attribute group.

This call keeps running until the switch date. That date is not set. On that date the agreed attributes are left out of the row. They are not sent empty. There is no agreed list yet.

Link — not a call

There is no payload for the link. F&O does not send it, and the Function App does not keep a second map.

  • One PIM folder stores one category id. The id is the same categoryKey text as /tree.
  • Several folders may store the same id.
  • Empty means that folder is not mapped. A child folder does not take its parent’s id.
  • The id used for a product is the id on the folder the master sits in. PIM does not walk up to a parent.
  • A rename or a move of the PIM folder does not change the id, and it does not rename or move the F&O category.
  • The holding folder is not mapped. No placement is sent for a product that is still there.

The field is on the folder in PIM. It is not on TEST.

NOT BUILT PIM → F&O

PIM calls the Function App directly. These calls do not go through the Data Lake. Nothing here has a body you can send, and there is no date.

OrderCallWhat PIM sends
1Attribute set-upThe agreed attributes only, and which category uses them. The category id is the same categoryKey as /tree.
2PlacementThe master item number and that category id. Sent only when the mapped category changes. Two folders that share one id do not cause a send. Variants are not rows. They follow the master.
3Attribute valuesThe full set the master shows, including a value it shows from a folder above. A missing value in that full set is removed in F&O. A master that does not yet have the full set is left out. Variant values are not sent.

PIM does not send its folders, its tree, or a category create, rename, inactivate, or delete. No return call starts until the attribute list exists and one writer per value has been proven on TEST.

Reply shape — same as today

HTTP 200 means the batch was read. A failed row is inside results and errors. 400 nothing applied. 413 the batch is too big. 401 bad key.

FieldMeaning

results[].actioncreated · updated · unpublished · released · unreleased · unchanged · failed
results[].codeOn a failure: VALIDATION, CONFLICT, or NOT_FOUND.

  "failed": 1,

Decide a retry from code and retryable, not from the sentence in error.
