ON TEST POST /api/v1/product-attributes

Same body as today. The attribute code must already be in the book from /attribute-definitions once the product exists. A code that is not in the book is ignored: is not in /attribute-definitions. The reply action is unchanged. Do not stop sending definitions, and send them before the values.

A waiting card with at least one attributeCode is held, one stored row per code. A newer row for the same code replaces it. The values are written when the card is placed. A row with no attribute list, and a product that is neither a catalogue item nor a waiting card, is NOT_FOUND, retryable: itemNumber not found; send it on /product-master first.

On a catalogue master or variant, a value whose group is not on that product’s folder is ignored, not failed: is not placed on a folder of this item. A code a person owns in Pimcore is not overwritten. Null, "", a text value that is only spaces, or isDeleted: true clears the object’s own value. Leaving the code out does not clear it. A boolean clear stores false, and GET /fo-product-values treats false as empty. Do not resend the same row in a loop.

An itemNumber row stores the code on the object that number finds. A variant’s itemNumber is found first. Otherwise the number is a master’s code, and the value is stored on the master, not on the folder. The comparison is the value stored on that object. A folder-only value counts as empty, so sending the value GET /fo-product-values showed stores it on the master when the master does not already store it. The next read then uses the master’s own value, and a later edit of the folder is not used for that code. Leave the code off the master row when F&O still has the number and the unit that read returned. Send the code when F&O has a different non-empty value. A decimal sent without a unit is stored with the attribute’s unit, or with mm when the attribute has none. A list is one code. The last value sent for that code is the one kept. The folder’s other values for that code are not added. There is no flag that sends a value without storing it.

A row that sends categoryKey instead of itemNumber finds the catalogue folder whose stored F&O id is that text. /tree does not write the id. A person types it on the folder, or POST /api/v1/fo-category-key writes it. No folder with that id is NOT_FOUND, retryable: no PIM folder is linked to category {id}; a person must store it in F&O category on the folder. The same id on two folders is CONFLICT, not retryable: categoryKey {id} is stored on N folders in PIM; a person must leave it on one. A value that is only the folder’s own code, with the id left empty, is NOT_FOUND. The folder must be a series, a range, or a product group. A type or a family is VALIDATION: categoryKey must be a series, range, or product group. The same categoryKey on /attribute-definitions uses this id lookup and accepts any catalogue folder that is not a master.

There is no switch date and no agreed list of attributes to leave out. Until that list exists, keep the current send.

Reply shape — same envelope

HTTP 200 means the batch was read, including when failed is greater than 0. A failed row is inside results and errors. 413 the batch is too big and nothing in that call is applied. 401 bad key. Judge a row by its own results[] entry. /product-master does not answer unchanged.
