How product data travels from F&O to Pimcore

Red Horse integration · end to end

The example follows one screw, 35006, whose length changes from 30 mm to 35 mm.

Part 1 — F&O

Where every product starts. We only read from it.

1 A product is changed

Someone edits a product in F&O. Only products with "Push to PIM" ticked travel on.

Example: The length of 35006 is set to 35 mm.
↓

2 A change folder appears

F&O drops the changed rows into a new folder, named after the time it was made.

Example: Folder "10:00" holds the 35 mm change.
↓

Part 2 — The conveyor (Data Factory)

Picks up change folders one at a time and hands them to our app.

3 Start the run

Started by hand today; a timer will start it every hour later.

Example: Adil starts a run at 10:15.
↓

4 Pick the next folder

A bookmark records the last folder done. The run takes the next one, oldest first, one per run.

Example: The bookmark says "09:00 done", so this run takes "10:00".
↓

5 Copy it

The folder is copied into our own storage, so we never work on F&O's live area.

Example: "10:00" is copied.
↓

6 Check the copy ✋

If the copy is incomplete, the run stops. The same folder is retried next run.

Example: An empty copy after a network hiccup stops the run; the next run copies "10:00" again.
↓

Part 3 — Our app sends the data, one kind at a time

Every step sends only what changed, waits if something it needs isn't in Pimcore yet, and keeps Pimcore's "got it" as a receipt.

7 Companies

The list of Red Horse companies.

Example: RH, SPI, RHU…
↓

8 Folder tree

The product folders, parents first. Today only Screws.

Example: Screws › 06-15546 › Standard › Carbon steel › 063333.
↓

9 Products

Each product and its variants, with name and allowed colours and sizes. A variant waits until its colour exists in Pimcore.

Example: 35006 is placed in folder 063333.
↓

10 Colours & sizes

The short codes variants use, with their full names.

Example: Code "59" = RAL 1003.
↓

11 Who sells it

Which companies sell each variant: "yes" when they start, "no" when they stop.

Example: Variant 35006-21-59-8-1 is sold by RH and SPI.
↓

12 Names

Name and description in every language, as written in F&O. A deleted language is emptied in Pimcore.

Example: The English name of 35006.
↓

13 Product facts

Each product's own facts, with the unit. A removed fact is cleared in Pimcore.

Example: Length 35 mm. This is our change arriving.
↓

14 List of facts

Which facts exist, their choices, and which folders use them.

Example: "Head type" with the choices Countersunk and Pan.
↓

Part 4 — Finish the folder

15 Health check ✋

If anything looks wrong, the run stops and the folder is retried next run.

Example: The folder tree can't be found, so the run stops instead of removing anything.
↓

16 Move the bookmark

Only now is the folder marked done.

Example: "09:00 done" becomes "10:00 done".
↓

17 Tidy up (paused)

Our copy is deleted after a good run. Switched off while testing.

Example: The copy of "10:00" is kept for now.
↓

Part 5 — Pimcore

18 Pimcore stores it

It answers every record: created, updated, unchanged, or "could not use this". What it doesn't confirm is resent.

Example: Pimcore answers "updated": 35006 now shows 35 mm.

What happens when…

…a product is unticked or deleted in F&O?

It is unpublished in Pimcore once. Nothing is removed without a clear signal.

…Pimcore is down?

The run stops; the same folder is retried next run. Nothing is lost.

…Pimcore loses data?

Adil asks for a full resend. It happened once on TEST: the folder tree was restored in one run.

✋ = a run can stop here. The bookmark then stays where it was, so the next run simply retries the same folder. Nothing is lost.

A record reaches Pimcore only when every ✅ in its box is true. If one is not true yet, it simply waits. It is never lost, and it goes on a later run once the condition is met.

🔑 Always needed, for every kind of data

  • ✅ Something changed since the last time it was sent. Unchanged data is not sent again.
  • ✅ That kind of data is switched on (live). Switched off = rehearsal only, nothing is sent.
  • ✅ The run is healthy. For example, the folder tree was found.

🏢 Companies

  • ✅ The company has a name in F&O.
  • ✅ It is not on the "leave out" list (internal codes such as DAT and GXN are left out).

🌳 Folder tree

  • ✅ It is in the "Product Catalogue" tree.
  • ✅ It is in a product type we send. Today that is Screws only.
  • ✅ The folder has a name, and its parent folder is sent too.
  • ✅ It is no deeper than 5 levels (type › plate › series › range › drawing).

🔩 Products

  • ✅ "Push to PIM" is ticked, on the main product and on each variant. Ticking the main product does not tick its variants.
  • ✅ The main product sits in one drawing folder (level 5) of the tree we send.
  • ✅ A variant's main product is sent too.
  • ✅ A variant's colour and size codes are already in Pimcore.
  • ✅ The item number is used only once.

🎨 Colours & sizes

  • ✅ It belongs to a main product that sits in a folder we send. It does not need "Push to PIM".
  • ✅ Its short code (for example "59") means only one colour. Clashing codes are held back.

🏷️ Who sells it

  • ✅ The company is a shop company: RH, RHU, ASW or SPI.
  • ✅ The product or variant is already in Pimcore.
  • ✅ The company is already in Pimcore.

🌐 Names

  • ✅ The product is already in Pimcore.
  • ✅ The text is the product's own. A variant does not borrow its main product's name.

📏 Product facts

  • ✅ The product is already in Pimcore.
  • ✅ The fact is on the list of facts in Pimcore (next box).
  • ✅ For a pick-list, the value is one of its choices.
  • ✅ The fact is linked to the product's folder (or a folder above it).
  • ✅ It is a business fact, not an F&O system field.

📚 List of facts

  • ✅ The fact type is one we understand: text, number, yes/no, or pick-list.
  • ✅ It belongs to an attribute group, and that group is linked to a folder we send.
  • ✅ A pick-list has at least one choice.

🚫 Never sent to Pimcore

Prices, stock and customer-specific data.

🗑️ When is something removed from Pimcore?

Only on a clear signal from F&O: it was deleted, or "Push to PIM" was unticked. Missing or late data never removes anything.
