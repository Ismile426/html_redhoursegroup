Two ways to keep the catalogue

Red Horse integration · PIM and F&O folders

From the 1 October discussion. Approach 1 keeps the same folders in PIM and F&O. Approach 2 keeps separate folders, joined by a link. Neither has been chosen. Nothing on this page is in operation.

What happens today

→
PIM
stores the same folders and the values that arrive

The folders are product type, family, series, range, and product group. PIM does not send folders or values back.

Order of arrival

No returnNothing is sent back. There is no call from PIM to F&O.

What this means

  • The order matters. A folder has to exist before a product can be put in it, and a product has to exist before its variant.
  • A value is stored on the product named on the row. Two products do not overwrite each other.
  • A folder in PIM is the folder F&O sent. Renaming it in PIM does not update F&O.
  • PIM holds content of its own that never came from F&O: the shop image and shop description per shop, the product-type icon, technical images, compliance documents, and label images.
  • F&O decides which shops a variant is released to.

The item number, the values F&O still owns, the names, and the release can stay. Under Approach 1 the folders change. A return of agreed attributes is new for both.

Approach 1 — the same folders, shown on both sides

The same folders are held on both sides. Move Carbon in PIM and the F&O category moves with it. There is no link table.

A move

The folder moves in PIM, and the same folder moves in F&O.

Orders keep the category they were posted with. A report on the invoice still shows the old category. A report on the item’s current category shows only the new one, so the earlier period is omitted from that category.

A delete

Once a product is released and orders exist, F&O cannot delete that category. Removing it in PIM does not remove it in F&O.

Advantages and disadvantages

Each situation below was named in the discussion. This is our reading. Where a point was not decided, the text says so.

Go-live, the first load

The folders exist on both sides for the first time.

For
  • One set of folders to agree and one to check. The two sides cannot diverge, because there is only one set.
  • No link to populate and no link to keep.
Against
  • The folders have to be correct before they are sent, because F&O then uses them on orders.

A range is moved after a year of sales

The situation described in the discussion: a year of sales is recorded on one category, then the product is moved to another.

For
  • One change, made in one place. Both systems match afterwards.
Against
  • The F&O category moves too. A report that reads the category on the invoice shows the product in two categories. A report that reads the item’s current category loses that first year.
  • Purchase orders and sales orders carry the category they were posted with, and reporting is built on that.

A category is discontinued

A product is released and orders already exist against the category.

For
  • There is no link to remove.
Against
  • F&O cannot delete a category that orders use. Removing it in PIM does not remove it in F&O, so the two sides no longer match and that has to be handled in F&O separately.

A new material value is introduced

Values entered once on a folder mean one folder per value. This was raised as a concern in the discussion.

For
  • The new folder reaches F&O through the same send as the rest.
Against
  • A new value means a new folder, and that folder is created in F&O, where orders may later use it.

Another system is added later

Named in the discussion as a reason to prefer Approach 2. No design was prepared for it.

Against
  • The second system needs its own copy of the same folders, and then both copies have to be kept.

Implementation effort

Both options need something PIM does not do today.

For
  • The smaller change of the two. There is no link to build and no link to maintain.
Against
  • Sending the folders out of PIM is new. It does not exist today.

Approach 2 — separate folders, joined by a link

PIM can place Carbon under a series. F&O can keep Carbon beside the other categories. The link is the only connection between them. Move Carbon in PIM and the F&O category stays.

The same PIM folders could later have a second set of rows to another system. That system was named as a reason, and it was not designed, so it is not shown.

A move

The PIM folder can move. The F&O category stays. The link row is what changes.

The invoice still keeps the category it was posted with. The link does not rewrite that history. It only records which F&O category the PIM folder refers to now.

A delete

Removing the connection deletes the link row. The F&O category stays when an order already uses it.

Advantages and disadvantages

Each situation below was named in the discussion. This is our reading. Where a point was not decided, the text says so.

Go-live, the first load

The folders exist on both sides for the first time.

For
  • The first load can still be one-to-one, so the first day matches Approach 1.
Against
  • A row has to exist for every folder before anything depends on it. That is additional setup at the start.
  • Where the link is kept was not decided. It was described as a screen in PIM, and also as something held outside PIM.

A range is moved after a year of sales

The situation described in the discussion: a year of sales is recorded on one category, then the product is moved to another.

For
  • The F&O category stays, so the category on the order is unchanged and the year of history remains complete.
  • PIM can reorganise the catalogue without changing F&O reporting.
Against
  • The row has to be updated. A move with no row update leaves the two sides describing different things.
  • Over time the two sets of folders no longer match, so a question about one has to be answered through the link.

A category is discontinued

A product is released and orders already exist against the category.

For
  • Removing the connection removes the row only. The F&O category stays, which is what F&O needs when orders use it.
  • PIM can discontinue its own folder without waiting on F&O.
Against
  • An F&O category with no row still exists. That category still has to be reviewed, and a decision made on what it is used for.

A new material value is introduced

Values entered once on a folder mean one folder per value. This was raised as a concern in the discussion.

For
  • The new folder can be added in PIM and linked to a category F&O already has.
Against
  • A new folder needs a new row before anything uses it.

Another system is added later

Named in the discussion as a reason to prefer Approach 2. No design was prepared for it.

For
  • The same PIM folders stay, with a second set of rows for the other system.
Against
  • This was stated as a reason, not as a plan. No second system was specified, and the effort for one is not known.

Implementation effort

Both options need something PIM does not do today.

For
  • Described in the discussion as more work and, in one view, safer, because of what a move does to order history.
Against
  • The link has to be built, maintained, and assigned an owner. PIM does not have it today.
  • Two sets of folders mean two places to check when something does not match.

What both options share

  • The item number is created in F&O.
  • A value can be entered once on a folder in PIM. The products under that folder show it. Material is entered on the range. Sent back, F&O receives the attribute and the value on the item number.
  • That return was described without category attributes and without product-group attributes. The list of attributes to send was not closed.
  • A value that changes per product, such as diameter, stays on the product.
  • The product holds the allowed configuration, colour, size, and style. The variant holds one choice from each list.
  • Shop and web content were asked about. No steps for them were agreed, so they are not included here.

What PIM already keeps

  • A folder tree: product type, family, series, range, product group.
  • A value entered on a folder, shown on the products underneath when those products have no value of their own.
  • Variants under the product.
  • Measures such as diameter and length.
  • A list of allowed configuration, colour, size, and style on the product, and one choice on the variant.
  • A rename or a move keeps the same folder. The path on screen changes.

This is enough for the value example above. Choosing Approach 1 or Approach 2 does not change where that value is typed.

What is new, for either option

  • A send from PIM back to F&O. That send does not exist today.
  • The agreed list of attributes to send. Only that list is sent back.
  • The value sent is the one the product shows, including a value it shows from a folder above. Variants are not the place F&O stores attribute values.
  • The current feed from F&O into PIM has to stop for those attributes on an agreed date. Until then the feed and a value typed in PIM are two writers of the same field.
  • A new attribute is added when it is agreed. It does not appear in the return by itself.

Notes that apply to both

This concern applies to both. Sorting by value adds a folder per value, so there are more folders than today. Discontinuing a value means reworking that folder. A value that differs per product, such as diameter, stays on the product and does not create folders.

For both: sending anything from PIM to F&O is new, and today’s feed into PIM has to stop for the agreed attributes on a date, or a value typed in PIM and a value arriving from F&O are two writers of the same field.

Shows the product’s material and diameter. Holds one configuration, for example Black, loose. The product holds the full allowed list.

If a value is sent back, F&O receives the value the product shows, on the item number. F&O does not repeat the folder structure for that value.

Assessment. Entering a value once, and letting the products below show it, fits PIM as it is. It does not require either option. Approach 1 is the smaller change to the folders, and it is the one that moves F&O categories when a folder is moved in PIM. Approach 2 leaves those categories in place and adds the link, which is the additional work. PIM can maintain the folders and the values for either choice. It does not maintain F&O’s order history.

Example only. This is not the live catalogue, and it is not a decision.
