Two ways to keep the catalogue

From the 1 October discussion. One option keeps a single folder structure in both systems. The other keeps a structure in PIM and a structure in F&O, with a link between them. Neither has been chosen. Nothing on this page is live.

What happens today

The folders are product type, family, series, range, and product group. PIM does not send folders or values back.

4The attribute list, and which folders each attribute belongs on.

StopNothing goes back. There is no call from PIM to F&O.

What this already means

  • The order matters. A folder has to exist before a product can be put in it, and a product has to exist before its variant.
  • A value lands on the product named on the row. Two products do not overwrite each other.
  • A folder in PIM is the folder F&O sent. Renaming it in PIM does not tell F&O anything.
  • PIM holds content of its own that never came from F&O: the shop image and shop description per shop, the product-type icon, technical images, compliance documents, and label images.
  • F&O decides which shops a variant is released to.

Both options below keep steps 1 to 8 for the things F&O still owns. What changes is who owns the folders, and whether anything travels back.

The two options

Rigid — one structure

The folders are kept in PIM and sent to F&O. F&O receives the same folders. There is no separate link table.

A rename or a move in PIM changes that folder in F&O as well.

Dynamic — two structures and a link

PIM keeps its own folders. F&O keeps its own categories. One row links a PIM folder to an F&O category. A change on one side does not rewrite the other.

A move

Rigid

The folder moves in PIM, and the same folder moves in F&O.

Orders keep the category they were posted with. A report on the invoice still shows the old category. A report on the item’s current category shows only the new one, so the earlier period drops off that category.

Dynamic

The PIM folder can move. The F&O category stays. The link row is what changes.

The invoice still keeps the category it was posted with. The link does not rewrite that history. It only says which F&O category the PIM folder points at now.

A delete

Rigid

Once a product is released and orders exist, F&O cannot delete that category. Removing it in PIM does not remove it in F&O.

Dynamic

Removing the connection deletes the link row. The F&O category stays when an order already uses it.

Pros and cons, in situations that were raised

Each situation below was named in the discussion. The reading is ours. Where something was left open, it says so.

Go-live, the first load

The folders exist on both sides for the first time.

Rigid
For
  • One structure to agree and one to check. Nothing can drift apart, because there is only one.
  • No link to populate and no link to keep.
Against
  • The structure has to be right before it is sent, because F&O then uses it on orders.
Dynamic
For
  • The first load can still be one-to-one, so day one looks the same as rigid.
Against
  • A row has to exist for every folder before anything depends on it. That is extra setup on day one.
  • Where the link is kept was not decided. It was described as a screen in PIM, and also as something kept beside PIM.

A range is moved after a year of sales

The situation walked through in the discussion: a year of sales sits on one category, then the product is moved to another.

Rigid
For
  • One move, one place to do it. Both systems agree afterwards.
Against
  • The F&O category moves too. A report that reads the category on the invoice shows the product in two categories. A report that reads the item’s current category loses that first year.
  • Purchase orders and sales orders carry the category they were posted with, and reporting is built on that.
Dynamic
For
  • The F&O category stays, so the category on the order is untouched and the year of history stays whole.
  • PIM can reorganise for how the catalogue should read, without asking what it does to F&O reporting.
Against
  • Someone has to update the row. A move with no row update leaves the two sides describing different things.
  • Over time the two structures stop looking alike, so a question about one has to be answered through the link.

A category has to be retired

A product is released and orders already exist against the category.

Rigid
For
  • Nothing extra to clean up, because there is no link.
Against
  • F&O cannot delete a category that orders use. Removing it in PIM does not remove it in F&O, so the two sides no longer match and that has to be handled in F&O separately.
Dynamic
For
  • Removing the connection removes the row only. The F&O category stays, which is what F&O needs when orders use it.
  • PIM can retire its own folder without waiting on F&O.
Against
  • An F&O category with no row still exists. Someone has to notice and decide what it is for.

A new material value is introduced

Values entered once on a folder mean one folder per value. This was raised as a concern in the discussion.

Rigid
For
  • The new folder reaches F&O through the same send as the rest.
Against
  • A new value means a new folder, and that folder lands in F&O where orders may later use it.
Dynamic
For
  • The new folder can be added in PIM and pointed at a category F&O already has.
Against
  • A new folder needs a new row before anything uses it.

This concern applies to both. Sorting by value adds a folder per value, so there are more folders than today. Retiring a value means reworking that folder. A value that differs per product, such as diameter, stays on the product and does not create folders.

Another system is added later

Named in the discussion as a reason to prefer the second option. Nothing for it was designed.

Rigid
Against
  • The second system needs its own copy of the same folders, and then both copies have to be kept.
Dynamic
For
  • The same PIM folders stay, with a second set of rows for the other system.
Against
  • This was a reason given, not a plan. No second system was drawn, and the effort for one is not known.

Effort to put in place

Both options need something PIM does not do today.

Rigid
For
  • The smaller change of the two. There is no link to build and no link to maintain.
Against
  • Sending the folders out of PIM is new. It does not exist today.
Dynamic
For
  • Described in the discussion as more work and, in one view, safer, because of what a move does to order history.
Against
  • The link is a thing that has to be built, kept, and owned by someone. PIM does not have it today.
  • Two structures mean two things to look at when something does not add up.

For both: sending anything from PIM to F&O is new, and today’s feed into PIM has to stop for the agreed attributes on a date, or a value typed in PIM and a value arriving from F&O are two writers of the same field.

What both options share

  • The item number is created in F&O.
  • A value can be entered once on a folder in PIM. The products under that folder show it. The example from the discussion was material on a series. Sent back, F&O receives the attribute and the value on the item number.
  • That return was described without category attributes and without product-group attributes. The list of attributes to send was not closed.
  • A value that changes per product, such as diameter, stays on the product.
  • The product holds the allowed configuration, colour, size, and style. The variant holds one choice from each list.
  • Shop and web content were asked about. No steps for them were agreed, so they are not in this picture.

What PIM already keeps

  • A folder tree: product type, family, series, range, product group.
  • A value entered on a folder, shown on the products underneath when those products have no value of their own.
  • Variants under the product.
  • Measures such as diameter and length.
  • A list of allowed configuration, colour, size, and style on the product, and one choice on the variant.
  • A rename or a move keeps the same folder. The path on screen changes.

This is enough for the value example above. Choosing rigid or dynamic does not change where that value is typed.

What is new, for either option

  • A send from PIM back to F&O. That send does not exist today.
  • The agreed list of attributes to send. Only that list goes back.
  • The value sent is the one the product shows, including a value it shows from a folder above. Variants are not the place F&O stores attribute values.
  • The current feed from F&O into PIM has to stop for those attributes on an agreed date. Until then the feed and a value typed in PIM are two writers of the same field.
  • A new attribute is added when it is agreed. It does not appear in the return by itself.

What each option adds

RigidDynamic
Folders The folders PIM already has are sent across, so F&O has the same ones. PIM can keep its folders. F&O keeps its categories. A link joins a PIM folder to an F&O category. The first load can still match them one-to-one.
A move Changes the folder in both systems. Reports that use the invoice category and reports that use the current category then disagree, as described above. Changes the PIM folder and the link. The F&O category stays, so old orders keep their category.
A removed folder F&O cannot delete a category that orders already use. The link can be removed. The F&O category stays when orders use it.
Where the link is kept There is no link table. The link can be a screen in PIM, or it can be kept beside PIM. That place is not chosen.
Another system later Another copy of the same folders. The same PIM folders, with another link. Not designed.

Reading of the fit. Entering a value once, and letting the products below show it, fits PIM as it is. It does not require either option. Rigid is the smaller change to the folders, and it is the one that moves F&O categories when someone moves a folder in PIM. Dynamic leaves those categories in place and adds the link, which is the extra work. PIM can maintain the folders and the values for either choice. It does not maintain F&O’s order history.
